# General Mini Agent Framework 项目身份重写设计

## 目标

将当前仓库的项目身份统一为 **General Mini Agent Framework**，移除旧项目名称、旧规划叙事和不准确的宣传性描述，为后续二次开发建立清晰基线。

## 范围

- 从头重写 `README.md`，只描述仓库当前已经存在的能力、结构、安装方式和运行方式。
- 重写 `PLAN.md` 与 `ROADMAP.md`，将其改为本项目的架构说明和后续扩展路线，不保留上游开发过程或宣传话术。
- 重写 `AGENTS.md` 与 `CLAUDE.md`，使开发约束和项目上下文与当前仓库一致。
- 清理 Python 模块说明、Demo 输出标题和 HTML Trace 标题中的旧身份或宣传性措辞。
- 保留现有目录结构、公共 Python API、环境变量、DeepSeek/OpenAI 兼容配置和运行行为。

## 不在本轮处理

- 不修复记忆写回、全局工具注册表、Debate 多轮控制等已有行为问题。
- 不重命名 `core`、`demo`、`tests` 包，也不引入新的打包结构。
- 不新增功能、依赖、Git 仓库或发布配置。

## 文档原则

- 项目名统一使用 `General Mini Agent Framework`。
- 文档以中文为主，保留必要的英文 API 和协议名称。
- 不使用难以验证的代码规模、能力覆盖率或来源描述。
- 已实现能力与规划能力明确分开。
- README 中的示例必须与当前公开 API 一致。

## 验证

- 全仓库检索旧名称和旧项目叙事，确认没有非必要残留。
- 检查 README 中的路径、依赖数量、测试数量和命令是否与仓库一致。
- 对 `core`、`demo`、`tests` 执行 Python 语法编译。
- 若当前环境具备依赖，则运行测试；否则明确记录未运行原因。
