# General Mini Agent Framework 0.4.1 后续版本路线规划

> 本文只定义版本依赖、进入条件、任务边界和退出条件。每个稳定版本开始实施前，必须单独完成
> 中文设计文档和中文详细实施计划，不得直接把本文当作代码修改清单。

## 总体原则

- `0.4.1` 完成并合入后才开始后续功能版本。
- 保持现有公共 API，破坏性命名迁移不得进入 `0.x` 补丁版本。
- 新能力必须覆盖同步和流式路径，异步能力必须明确自己的同步互操作边界。
- 状态、工具、策略、事件和上下文继续保持 Agent 实例与单次运行隔离。
- 外部调用必须有超时、错误分类、脱敏和离线替代实现。
- 可选依赖继续延迟加载，不进入默认运行时依赖。
- 保留现有回归测试；每版只增加直接约束新契约和高风险边界的少量测试。
- 每个版本完成后更新 README、PLAN、ROADMAP、CHANGELOG 和包版本。

## 依赖顺序

```text
0.4.1 发布基线
  -> 0.5.0 结构化工具结果与授权
  -> 0.6.0 异步模型、Agent 与工具取消
  -> 0.7.0 统一运行标识、事件与 JSON trace
  -> 0.7.1 HTML trace 稳定化与离线示例
  -> 0.8.0 串行、并行和条件编排
  -> 0.9.0 模型兼容层、统一配置、日志与命名空间迁移
  -> 1.0.0 公共 API、命名空间与发布稳定化
```

工具授权先于异步，确保所有执行入口共用同一安全决策。异步先于并行编排，确保取消和超时
不是线程包装出来的伪语义。统一事件先于编排，确保多个节点和子运行可以追踪、聚合和导出。

## 阶段 1：0.5.0 结构化工具结果与授权

### 进入条件

- `0.4.1` 已合入目标分支，工作区干净。
- Python 3.12 与 3.14 CI、wheel 构建和干净安装验证通过。
- `core.tools.ToolExecutionResult` 与 Agent 同步/流式工具观察路径未被并行任务修改。

### 任务顺序

1. 定义 JSON 值、工具执行请求、授权决策和授权策略协议。
2. 让 `ToolRegistry` 对字符串和 JSON 值生成确定性的模型观察文本。
3. 对非 JSON 值、NaN、Infinity 和非字符串对象键返回结构化序列化错误。
4. 在参数绑定成功后、工具函数调用前执行实例级授权策略。
5. 授权拒绝和策略异常都必须 fail closed，不得调用工具函数。
6. 让 `Agent.run()` 与 `Agent.run_stream()` 注入同一策略并保留一致的错误码。
7. 导出稳定契约，更新最小 Demo、README、PLAN、ROADMAP 和 CHANGELOG。
8. 将版本提升为 `0.5.0`，完成一次全量离线验证和发行包验证。

### 明确不做

- 不提供同步函数的强制终止。
- 不增加异步 callable、超时或取消 token。
- 不实现用户、租户或 RBAC 系统。
- 不允许策略修改工具参数或工具返回值。

### 测试预算

最多新增 6 个测试函数：JSON 结果、序列化失败、授权拒绝、策略 fail-closed、注册表隔离、
同步/流式 Agent 一致性。公共导出与文档要求并入现有契约测试，不新建重复测试模块。

### 退出条件

- JSON 工具结果在同步与流式观察中使用相同确定性文本。
- 非法结果不会以 Python `repr` 冒充 JSON。
- 授权策略始终在工具副作用之前运行。
- 两个 Agent 的工具策略互不影响。
- 未配置策略的现有调用行为保持兼容。
- 完整测试、lint、编译、wheel 构建与干净安装通过。

## 阶段 2：0.6.0 异步模型、Agent 与工具取消

### 进入条件

- `0.5.0` 的工具请求、授权决策和结构化结果契约稳定。
- 同步 Agent 与流式 Agent 已通过同一工具执行入口。

### 任务顺序

1. 定义 `AsyncChatModel` 与异步流式模型协议，不修改现有同步协议。
2. 使用 `httpx.AsyncClient` 实现异步 Chat Completions 和 SSE，复用现有解析规则。
3. 为工具注册表增加独立异步执行入口，原生等待 async callable。
4. 明确同步 callable 在异步入口中使用工作线程执行，取消只能停止等待，不能保证终止线程函数。
5. 增加每次工具调用的 deadline，并用 `asyncio.timeout()` 约束异步等待。
6. 对 `CancelledError` 原样向上传播，不转换为普通工具错误。
7. 实现 `Agent.run_async()` 和异步生成器 `Agent.run_stream_async()`。
8. 保持消息、usage、trace、内存写回和停止原因与同步契约一致。
9. 更新 Demo、稳定导出与文档，将版本提升为 `0.6.0`。

### 明确不做

- 不提供异步 Debate 或通用编排。
- 不声称可以强制杀死已在线程中运行的同步工具。
- 不为 ChromaDB 自动创建异步包装。

### 测试预算

优先复用脚本化模型 fixture。新增测试只覆盖：异步文本完成、异步工具链、流式聚合、deadline、
取消传播、同步 callable 兼容、状态隔离和同步/异步关键结果一致性。相似失败使用参数化。

### 退出条件

- 异步路径不阻塞模型 HTTP 调用。
- 异步工具超时与调用方取消具有不同错误语义。
- 取消不会写入不完整会话，也不会被误报为模型错误。
- 一个 Agent 的多个异步运行不共享运行态。

## 阶段 3：0.7.0 统一运行标识、事件与 JSON trace

### 进入条件

- 同步、流式和异步 Agent 的终态语义稳定。
- 所有入口都有明确的单次运行边界。

### 任务顺序

1. 定义不可变的 `RunContext`，包含 `run_id`、可选 `parent_run_id` 和开始时间。
2. 定义事件 envelope，承载运行标识、单调序号、事件类型、时间戳和结构化 payload。
3. 保留现有 `StreamEvent`，通过适配层产生统一事件，避免直接破坏稳定 API。
4. 为模型请求、工具调用、停止原因和错误增加耗时与脱敏摘要。
5. 让 Debate 子 Agent 运行通过 `parent_run_id` 关联到 Debate 运行。
6. 增加确定性的 JSON trace 导出，不包含 callable、异常对象或密钥。
7. 明确事件 sink 失败不能伪装成模型失败，并定义传播或隔离策略。
8. 更新 trace 文档、示例和版本元数据。

### 测试预算

测试集中于 ID 隔离、父子关系、事件排序、JSON 往返、密钥脱敏和 sink 失败边界；不逐个复制
已有 Agent 行为测试。

### 退出条件

- 每次运行有唯一 ID，同一运行内事件序号严格递增。
- Debate 与子 Agent 的父子关系可从 JSON trace 重建。
- 同一已完成结果重复导出得到稳定结构。
- 任何错误摘要都不泄露认证头或 API Key。

## 阶段 4：0.7.1 HTML trace 稳定化与离线示例

### 进入条件

- `0.7.0` JSON trace schema 已稳定。
- HTML 渲染器可以只消费结构化导出，不推断运行状态。

### 任务顺序

1. 将 HTML 渲染输入切换到稳定 JSON trace schema。
2. 增加按角色、事件类型、停止原因和错误状态过滤。
3. 增加两个运行的 usage、耗时、错误和角色轮次对比。
4. 保持静态单文件 HTML，不增加前端构建链。
5. 新增完全离线的脚本化模型 Demo，覆盖单 Agent、工具调用和 Debate。
6. 补充最小 API 示例与常见问题。
7. 将 HTML trace 从实验性能力提升为稳定能力并发布 `0.7.1`。

### 测试预算

保留少量 HTML 内容契约测试，主要验证 JSON 数据嵌入、过滤字段和危险文本转义；不对 CSS
像素和浏览器原生行为编写单元测试。

### 退出条件

- 离线 Demo 不读取 `.env`，不访问网络。
- HTML 能打开两个真实导出并完成过滤和对比。
- 用户数据经过安全转义，不可注入脚本。

## 阶段 5：0.8.0 串行、并行和条件编排

### 进入条件

- 异步 Agent、取消语义、统一事件和父子 run ID 均已稳定。

### 任务顺序

1. 定义最小节点协议和结构化节点输入/输出，不创建 DSL。
2. 实现按声明顺序执行的串行节点。
3. 使用异步任务组实现有界并行节点，并定义 fail-fast 与 collect-errors 两种显式策略。
4. 实现只接受调用方 predicate 的条件路由，不让模型隐式修改工作流图。
5. 为每个子节点分配 run ID，并关联到工作流父运行。
6. 定义取消、部分结果、usage 聚合和错误传播边界。
7. 提供由现有 Agent 和 Debate 组成的最小示例。
8. 更新稳定导出、文档和版本元数据。

### 明确不做

- 不增加持久化调度、分布式队列、可视化图编辑器、循环 DSL 或动态代码执行。

### 退出条件

- 并行度有明确上限，取消可传递到未完成异步节点。
- 条件只读取已完成的结构化输出。
- 重复运行不共享节点结果或错误。
- 所有节点事件可关联到同一工作流父运行。

## 阶段 6：0.9.0 模型兼容层、统一配置、日志与命名空间迁移

### 进入条件

- 模型请求、事件和错误摘要已经形成稳定边界。

### 任务顺序

1. 定义服务能力描述，不通过模型名称猜测特性。
2. 将 tool choice、usage、流式结束原因等差异放入显式适配器。
3. 建立环境变量、配置文件和代码参数的确定性优先级。
4. 校验 endpoint、模型名、超时和上下文窗口，不记录密钥值。
5. 使用标准库 logging 增加可注入 logger，不配置进程级 handler。
6. 为 DeepSeek 与通用 OpenAI 兼容端点提供最小适配示例。
7. 将正式实现迁移到 `general_mini_agent`，保留带弃用警告的薄 `core` 兼容层。
8. 更新错误分类、迁移文档和版本元数据。

### 退出条件

- 核心 Agent 不包含厂商条件分支。
- 配置错误在首次网络请求前失败。
- 日志可关联 run ID，默认不输出消息正文和凭据。
- 新旧命名空间导出对象身份一致，文档明确 `core` 将在 `1.0.0` 删除。

## 阶段 7：1.0.0 稳定发布

### 进入条件

- `0.9.x` 至少完成一次补丁发布演练。
- 所有稳定模块具有公共导出、文档、离线 Demo 和兼容性验证。

### 任务顺序

1. 盘点公共 API，删除从未稳定的兼容导出或给出正式弃用周期。
2. 删除 `0.9.x` 已弃用的 `core` 兼容包，只发布 `general_mini_agent` 正式命名空间。
3. 固化事件和 JSON trace schema 的版本字段。
4. 定义最低 Python 版本支持周期与依赖升级策略。
5. 建立变更类型、弃用、迁移和安全修复政策。
6. 完成从空环境安装到离线 Demo 的发布候选验证。
7. 发布候选通过后更新全部稳定文档并创建 `1.0.0`。

## 跨版本停止条件

出现以下任一情况时，不得开始下一阶段：

- 上一版本尚未合入或 CI 未通过；
- 当前设计依赖一个尚未稳定的上游契约；
- 同步、流式或异步路径的行为差异没有被文档明确说明；
- 新能力要求破坏公共 API，但版本号仍按补丁或普通次版本处理；
- 为满足测试数量而删除隔离、失败边界或密钥脱敏回归保护；
- 文档描述了尚未实现或无法离线验证的能力。
